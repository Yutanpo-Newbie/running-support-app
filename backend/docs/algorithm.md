# Route Suggestion Algorithm

## 概要

本ドキュメントでは、ランニングサポートアプリにおけるルート提案アルゴリズムの設計方針をまとめる。

本アプリでは、ユーザーが指定したスタート地点、希望走行距離、好み条件をもとに複数のランニングルート候補を生成し、各ルートに対してスコアを計算する。  
最終的に、総合スコアである `total_score` が低い順にルート候補を並べ、ユーザーに提案する。

---

## 入力

ルート提案APIでは、以下の情報を入力として受け取る。

| 項目 | 内容 |
|---|---|
| start.lat | スタート地点の緯度 |
| start.lon | スタート地点の経度 |
| distance_km | 希望走行距離 |
| avoid_traffic | 車通り・交通混雑を避けたいか |
| avoid_signals | 信号数を少なくしたいか |
| avoid_intersections | 交差点・分岐点を少なくしたいか |
| elevation_mode | 高低差の好み |

---

## 出力

APIは、複数のルート候補を返す。

各ルート候補には以下を含める。

| 項目 | 内容 |
|---|---|
| id | ルートID |
| name | ルート名 |
| distance_km | ルート距離 |
| elevation_gain_m | 累積上昇量 |
| signals | 信号数 |
| intersections | 交差点・分岐点数 |
| traffic_score | 車通り・交通混雑リスク |
| total_score | 総合スコア |
| coordinates | 緯度経度の座標列 |
| geometry | GeoJSON LineString |
| turn_points | 音声案内地点 |

---

## 現段階の仮ルート生成

現段階では、OpenStreetMapやOSMnxには接続していない。  
そのため、スタート地点を中心に仮の周回ルートを生成している。

処理の流れは以下の通りである。

1. スタート地点の緯度・経度を取得する
2. 希望距離 `distance_km` から、ルートの広がり幅 `base_m` を計算する
3. スタート地点から北・東・西・南方向に仮の経由地点を生成する
4. 三角形または四角形に近い周回ルートを3本生成する
5. 各ルートの距離を計算する
6. 各ルートのスコアを計算する
7. `total_score` が低い順に並び替えて返す

---

## 仮ルート生成の考え方

現在は、道路ネットワークに沿った経路ではなく、緯度経度を直接ずらして仮の座標を作成している。

例：

```text
route_test001：北東方向に広がる三角形ルート
route_test002：東側に広がる四角形ルート
route_test003：西側に広がる四角形ルート
